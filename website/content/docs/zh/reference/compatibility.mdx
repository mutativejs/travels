## 运行时支持

Travels 在以下环境经过测试：

- Node.js 22.x
- Node.js 24.x
- 通过 Vitest 运行、类似浏览器的 jsdom 环境

Node.js 22 是最低支持的运行时版本。该包以 ESM、CJS、UMD 与 TypeScript 声明文件的形式分发。

## 浏览器支持

Travels 面向支持所需标准 JavaScript 与 JSON API 的现代浏览器。持久化示例会在环境支持时使用 `localStorage`、IndexedDB 与 BroadcastChannel。

Mutative 2 的构建以 ES2018 为目标，并通过 `process.env.NODE_ENV` 选择开发版或生产版构建。会定义 `NODE_ENV` 的打包器能同时处理两种构建。不使用打包器时，请加载 `mutative/dist/mutative.esm.production.min.mjs` 或 Mutative 的 UMD 构建，因为 Mutative 默认的 ES 模块需要 `process` 全局变量。

## peer 依赖

`mutative` 是 peer 依赖，支持 `^2.0.0`。不支持 Mutative 1.x，因为其部分补丁无法撤销它们记录的变更。测试套件针对仓库固定的开发版本运行。

## 官方绑定

v3 官方绑定使用公开的工厂能力，而不是内部构造函数：

| 绑定 | 绑定版本 | 支持的 Travels 版本 | 恢复历史记录的交接方式 |
| --- | --- | --- | --- |
| `use-travel` | `3.x` | `^3.0.0` | `restoreTravels(snapshot)`，然后 `useTravelStore` |
| `zustand-travel` | `3.x` | `^3.0.1` | `travel(initializer, { snapshot })` |

每个绑定的主版本都声明与 Travels 相同的 `mutative` peer 范围（`^2.0.0`），因此三个包可以一起安装而不会产生 peer 冲突。各绑定的主版本要求 Travels 3，从而让工厂重载、原子恢复路径、只读共享视图与控制能力共享同一份稳定契约。先发布并安装核心包的主版本，再基于该已发布产物验证并发布每个绑定的主版本。由绑定拥有的时间线仍为不可变模式，并且绑定会拒绝已移除或不兼容的所有权选项，而不是静默丢弃它们。

## 状态兼容性

状态、保留的补丁值与历史记录元数据若由普通对象、稠密数组、字符串、除 `-0` 之外的有限数字、布尔值与 `null` 构成，则受支持。路径必须是 Travels 可接受的 JSON Pointer 字符串，或由字符串与有限非负整数组成的稠密数组；其他值都是无效的路径段。对象形式的快照字段与补丁容器字段必须是自有数据属性；访问器与继承字段会被拒绝，且不会对它们求值。恢复的历史记录容器、补丁组、数组路径与元数据列表，必须是不含自定义自有属性或自定义原型的普通稠密数组；冻结的普通数组可以接受。`bigint` 会让 `JSON.stringify` 抛出异常；`NaN` 与无穷大会变成 `null`，而 `-0` 会变成 `0`。请在应用边界处规范化这些值。数组空洞、自定义属性以及自定义或 `null` 原型，都无法在补丁重放与 JSON 持久化后保留下来；请用 `null` 填充空洞，并使用普通数组与对象。Mutative 默认不会为 `null` 原型状态字典创建草稿，因此嵌套写入可能无法生成可撤销的补丁。即使不兼容的值或路径只保留在较旧的补丁中，也仍会使快照不安全。

不可变与可变两种运行时模式都会拒绝 Map 与 Set。Travels 会在提交更新前检查初始状态与新生成的补丁载荷；结构校验下的恢复也会拒绝状态或保留补丁中的集合类型。在传给 Travels 之前，请把 Map 条目转换为普通记录或稠密条目数组，把 Set 值转换为稠密数组；持久化编解码器必须生成这些受支持的形状，而不能把集合解码回 Travels 状态。

## 版本管理

Travels 遵循 semver：

- 补丁版本修复缺陷，不会有意更改 API。
- 次版本可以新增 API 与警告，同时保持现有行为不变。
- 主版本可能更改公共 API、持久化模式语义或运行时支持。

持久化的历史记录快照包含模式版本。升级存储格式时，使用 `Travels.deserialize(..., { migrate })`。
