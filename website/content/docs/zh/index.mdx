Travels 是一个与框架无关的状态历史引擎，为应用提供可靠的撤销/重做能力。它记录正向与反向 JSON Patch，因此状态庞大、编辑频繁而细微的应用也能保留紧凑的时间线，将其持久化，并在之后恢复。

你可以用熟悉的修改语法编写更新。Travels 默认通过 [Mutative](https://mutative.js.org/) 生成不可变状态；可变模式与受控日志则支持响应式 Store 和由外部持有的状态。

<Callout type="info" title="Travels 3">
第 3 版采用显式工厂函数、唯一的原子持久化恢复路径、只读共享视图，并将“拥有状态的时间线”和“外部日志”拆分为不同能力。正在升级？请先阅读[迁移指南](/zh/docs/migration)。
</Callout>

## 一分钟完成一个完整示例

```ts
import { createTravels, restoreTravels } from 'travels';

const travels = createTravels(
  { title: '未命名文档', tags: [] as string[] },
  { maxHistory: 100 }
);

const unsubscribe = travels.subscribe(({ state, position }) => {
  render(state, position);
});

travels.setState(
  (draft) => {
    draft.title = '我的文档';
    draft.tags.push('草稿');
  },
  { label: '编辑文档' }
);

travels.back();    // 撤销整次编辑
travels.forward(); // 重做

const snapshot = travels.serialize();
const restored = restoreTravels(snapshot);
```

下一步是[快速开始](/zh/docs/getting-started/quick-start)，它会逐一解释这条流程中的每个部分。

## 什么时候适合使用 Travels

Travels 针对历史体积、持久化和可重放的操作日志进行了优化。它尤其适合可视化编辑器、表单搭建器、本地优先应用、工作流设计器，以及其他需要让用户安全探索的编辑场景。

| 你的优先级 | 推荐方案 |
| --- | --- |
| 状态大、更新小、需要长期保留历史 | Travels |
| 需要持久化或传输撤销/重做历史 | Travels |
| 状态小、只需短期本地历史、追求最低更新延迟 | 快照栈可能更简单也更快 |
| 多用户并发冲突消解 | 使用 CRDT/OT 系统；Travels 本身不负责冲突消解 |
| 每次更新都替换完整状态 | 按你的工作负载比较快照与补丁的成本 |

完整的取舍讨论见[选择合适的方案](/zh/docs/getting-started/choosing-travels)。

## 公开构建模块

- `createTravels()` 创建一条由 Travels 掌管状态更新的时间线。
- `createPatchableTravels()` 为持久化状态增加编译期与即时运行时校验。
- `createTravelJournal()` 记录来自外部状态所有者的补丁对。
- `restoreTravels()` 与 `restoreTravelJournal()` 恢复经过完整校验的快照。
- `Travels.deserialize()` 解码、迁移并校验持久化输入。
- `getControls()` 为 UI 组件暴露一个窄而只读的导航接口。

所有导出都记录在 [API 参考](/zh/docs/api-reference)中。
