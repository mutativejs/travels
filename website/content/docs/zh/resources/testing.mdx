Travels 结合了基于示例的测试、基于属性的测试、浏览器测试、包使用方测试、覆盖率测试与变异冒烟测试。

## 变异冒烟测试

运行：

```bash
pnpm run test:mutation:smoke
```

该冒烟套件会临时引入一小组高价值的正确性回归，并验证针对性测试确实失败。每个源文件都会在 `finally` 块中还原。这些变异覆盖反向重放顺序、受控日志的补丁对校验，以及可变事务回滚的完整性。

这是有意设置的确定性关卡，而不是大规模的概率性变异活动。只要某个缺陷修复依赖于行覆盖率本身无法保护的细微运算符、边界条件或回滚步骤，就应补充一个变异。

## 热路径预算

运行：

```bash
pnpm run benchmark:hotpath
```

矩阵基准测试为 `setState` 吞吐量与序列化历史记录大小把关。它不覆盖撤销/重做导航或受控日志：曾有一项变更让受控导航比 2.1.0 系列慢 53 倍、外部提交慢 5.5 倍，却仍通过了检查，未被察觉。

`benchmarks/hot-path-check.js` 测量 `setState`、导航、事务以及两条受控日志路径的单次操作开销，并在任一项超出预算时使构建失败。这些预算属于数量级层面的冒烟上限，设置得远高于实测开销，以免共享 CI 运行器出现偶发失败；同样出于这一原因，每个场景取三次运行中的最佳结果。它们不是百分比级别的漂移检测器。只有在取得可测量的改进时才应收紧预算；每当有新操作进入时间线的热路径时，都应增加一个场景。
