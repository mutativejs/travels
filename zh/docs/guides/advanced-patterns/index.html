拦截与修改操作

subscribe() 可以让你观察状态变化，却无法阻止或修改操作。若要在执行前加入校验、权限或转换数据，需要包装 Travels 的方法。

包装 setState() 时必须保留被替代契约的两部分：把可选的第二个 metadata 参数继续传递下去，否则调用方附加到历史条目上的标签就会丢失；同时允许函数更新器修改草稿或返回新状态。下面的每个示例都兼顾了这两点。

replaceStateWithoutHistory() 通过 setState() 应用更新，所以 setState() 包装器对它同样生效。除非该调用抛出异常，否则它会清空历史记录。因此，如果包装器通过提前返回来阻止更新（校验和节流示例就是如此），旧状态会保留，但不会留下任何可撤销的内容。若要阻止替换并保留历史记录，应改为抛出异常，就像常见模式中的 withValidation() 那样；此时 replaceStateWithoutHistory() 会抛出同一个错误。
